# Flight Analyzer 科研网离线部署说明

本文档适用于通过光盘把 Flight Analyzer 部署到无法访问互联网的 Windows 10 科研网。客户端和服务器均可打包为独立 EXE；客户端使用本地 SQLite，统一服务器使用 MySQL。

## 1. 部署架构

```text
客户端 Windows 10                         科研网服务器 Windows 10
┌────────────────────────┐               ┌──────────────────────────┐
│ FlightAnalyzer.exe     │   HTTP 9000   │ FlightAnalyzerServer.exe │
│ React + FastAPI        │ ────────────> │ FastAPI / 同步服务        │
│ pywebview              │               │                          │
│ SQLite 本地缓存         │               │ MySQL 8 权威数据库         │
└────────────────────────┘               └──────────────────────────┘
```

- 客户端不需要安装 Python、Node.js 或 MySQL。
- 服务器不需要安装 Python，但必须安装 MySQL 8.x。
- 客户端只访问服务器的 TCP `9000`，不直接访问 MySQL `3306`。
- MySQL 应只监听服务器本机或由防火墙限制为仅服务器应用可访问。

如果不需要多机共享和同步，也可以只部署 `FlightAnalyzer.exe`。此时将客户端 `server_base_url` 留空，所有数据保存在本地 SQLite。

## 2. 总体顺序

推荐严格按以下顺序制作和部署：

```text
1. 冻结待发布代码版本
2. 在制品环境定稿机型
3. 生成内置机型 seed
4. 准备客户端和服务器配置模板
5. 打包客户端 EXE
6. 打包服务器 EXE
7. 制作光盘并记录 SHA256
8. 科研网服务器安装、初始化 MySQL
9. 部署并启动 FlightAnalyzerServer.exe
10. 修改默认管理员密码并创建正式用户
11. 部署客户端及现场 flight_analyzer.ini
12. 用户首次在线登录、同步和验收
```

机型预置必须在打包之前完成。用户预置推荐在科研网服务器启动之后完成，不要把正式用户密码或密码哈希嵌入客户端 EXE。

## 3. 构建机准备

构建必须在与目标机架构一致的 Windows 环境中进行。当前目标为 64 位 Windows 10，因此应使用 64 位 Python 和 PyInstaller。

```powershell
# 客户端构建及运行依赖
.\.venv\Scripts\pip.exe install -r requirements.txt

# 独立的最小服务端构建环境。不要复用客户端或 Anaconda 全量环境。
py -3.12 -m venv .venv-server
.\.venv-server\Scripts\pip.exe install -r requirements-server-build.txt

# 前端依赖
Set-Location .\frontend
npm install
Set-Location ..
```

构建机可以联网准备依赖；科研网目标机不需要这些开发工具。

## 4. 机型预置

在制品服务器中维护并确认所有机型、数据类型、列定义和解析规则。项目根目录准备临时 `flight_analyzer.ini`，其中 `[local].server_base_url` 指向制品服务器，并在 `[server_auth]` 填写有读取权限的账号。

```powershell
.\.venv\Scripts\python.exe .\script\generate_builtin_model_seeds.py
```

输出文件：

```text
backend\builtin_model_seeds.json
```

随后再打包客户端和服务器。同一版客户端与服务器应使用同一份 seed。首次启动时：

- 客户端把缺失机型写入本地 SQLite。
- 服务器把缺失机型写入 MySQL。
- 已有相同 `server_id`、`client_uid` 或名称的机型不会被覆盖。

### 用户预置说明

当前版本不应使用 `builtin_model_seeds.json` 预置正式用户：

- 服务器用户列表 API 不返回密码哈希，当前生成文件中的 `password_hash` 为 `null`。
- 本地种子加载器会跳过没有密码哈希的用户。
- 直接手工补充密码哈希会带来 EXE 可提取和离线破解风险。
- 当前加载逻辑会在每次启动时更新有效用户种子，存在覆盖本地改密结果的风险。

推荐流程是：服务器部署完成后创建用户，每名用户在服务器可用时至少成功登录客户端一次。客户端会缓存验证信息，之后服务器暂时不可达时仍可离线登录。

## 5. 打包客户端

项目根目录的构建期 `flight_analyzer.ini` 只应包含 `[local]` 和 `[dev]` 所需值。打包规则不会把 `[server]`、`[mysql]`、`[server_auth]` 嵌入客户端。

```powershell
.\script\build.ps1
```

输出：

```text
packaging\dist\FlightAnalyzer.exe
```

现场 `flight_analyzer.ini` 放在客户端 EXE 同目录，并覆盖打包时的配置：

```ini
[local]
; 留空则使用 %APPDATA%\FlightAnalyzer
data_dir = D:\FlightAnalyzerData
server_base_url = http://10.0.0.12:9000/api

[dev]
load_local = true
```

注意：

- 地址必须带 `/api`。
- 客户端配置不得包含 MySQL 密码。
- `data_dir` 目录必须允许当前 Windows 用户读写。
- 留空 `data_dir` 时，不同 Windows 账号使用各自的 `%APPDATA%` 数据库。

## 6. 打包服务器

执行：

```powershell
.\script\build-server.ps1
```

或：

```bat
script\build-server.bat
```

脚本默认使用独立的 `.venv-server`，其中只安装服务器运行依赖和 PyInstaller。不要把 pywebview、openpyxl、pytest 等客户端或开发依赖安装进该环境。脚本会检查依赖、运行 PyInstaller、执行无数据库运行时检查，并输出：

```text
packaging\dist\server\
├── FlightAnalyzerServer.exe
├── flight_analyzer.ini.example
├── start-server.ps1
└── SHA256.txt
```

服务端 EXE 包含 Python、FastAPI、uvicorn、SQLAlchemy、PyMySQL、同步服务代码和内置机型 seed，不包含 React 前端、pywebview 或 WebView2。

需要使用其他最小虚拟环境时可以显式指定：

```powershell
.\script\build-server.ps1 -BuildVenv D:\BuildEnvs\flight-server
```

构建后可以在没有 MySQL 的构建机上执行无数据库检查：

```powershell
.\packaging\dist\server\FlightAnalyzerServer.exe --check-runtime
```

该命令输出配置路径、监听地址、数据目录、数据库驱动和 API 路由数量；它会加载服务端及 `mysql+pymysql` 方言，但不会建立 MySQL 网络连接，也不输出数据库密码。只检查配置时可使用 `--check-config`。

## 7. 光盘内容

推荐光盘目录：

```text
FlightAnalyzer-Release\
├── Client\
│   ├── FlightAnalyzer.exe
│   ├── flight_analyzer.ini.example
│   ├── SHA256.txt
│   └── MicrosoftEdgeWebView2RuntimeInstallerX64.exe   # 可选兜底
├── Server\
│   ├── FlightAnalyzerServer.exe
│   ├── flight_analyzer.ini.example
│   ├── start-server.ps1
│   └── SHA256.txt
└── MySQL\
    └── MySQL 8.x 64 位完整离线安装包
```

最小情况下可以只导入“服务器 EXE + MySQL 安装包 + 启动脚本”。但配置文件仍然需要存在：可以单独携带模板，也可以由单位自己的部署脚本在现场生成。独立配置文件更便于更换 IP、端口、数据目录和数据库密码，不需要重新打包 EXE。

## 8. 科研网服务器首次部署

### 8.1 安装 MySQL

使用完整离线安装包安装 MySQL Server 8.x，并设置为 Windows 自动启动服务。常见服务名为 `MySQL80`，以现场安装结果为准。

只需首次安装一次。以后启动服务器时不应再次运行 MySQL 安装程序。

### 8.2 创建数据库和应用账号

使用 MySQL 管理员执行：

```sql
CREATE DATABASE flight_analyzer
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER 'flight'@'127.0.0.1' IDENTIFIED BY '替换为随机强密码';
GRANT ALL PRIVILEGES ON flight_analyzer.* TO 'flight'@'127.0.0.1';
FLUSH PRIVILEGES;
```

不要让客户端访问 MySQL，也不需要对科研网开放 TCP `3306`。

### 8.3 配置服务端

将 `flight_analyzer.ini.example` 复制为 EXE 同目录的 `flight_analyzer.ini`：

```ini
[server]
host = 0.0.0.0
port = 9000
data_dir = D:\FlightAnalyzerServer\data

[mysql]
host = 127.0.0.1
port = 3306
database = flight_analyzer
user = flight
password = 与建库时一致的强密码
charset = utf8mb4

[dev]
load_server = true
```

建议限制配置文件读取权限，只允许服务器管理员和运行服务端程序的 Windows 账号访问。

### 8.4 防火墙

管理员 PowerShell 执行：

```powershell
New-NetFirewallRule `
  -DisplayName "Flight Analyzer Server 9000" `
  -Direction Inbound `
  -Protocol TCP `
  -LocalPort 9000 `
  -Action Allow
```

应根据科研网网段进一步限制 `RemoteAddress`。

### 8.5 启动

管理员 PowerShell 进入服务器目录：

```powershell
.\start-server.ps1
```

默认行为：

1. 检查并启动 `MySQL80` 服务。
2. 检查 `http://127.0.0.1:9000/api/health` 是否已有实例。
3. 启动 `FlightAnalyzerServer.exe`。
4. 在 30 秒内轮询健康接口。

如果 MySQL 服务名或端口不同：

```powershell
.\start-server.ps1 -MySqlServiceName MySQL -ServerPort 9100
```

`-ServerPort` 必须和 `flight_analyzer.ini` 中的端口一致。

首次启动会自动创建业务表和内置管理员：

```text
用户名：admin
初始密码：123456
```

必须立即登录、修改默认密码并创建正式用户。

### 8.6 自动启动

MySQL 应配置为 Windows 自动启动服务。`FlightAnalyzerServer.exe` 可以通过以下任一方式实现开机启动：

- Windows 任务计划程序，以专用账号在系统启动时运行。
- 单位批准的 Windows 服务包装器。
- 人工运行 `start-server.ps1`。

正式环境推荐任务计划或 Windows 服务，避免服务器重启后等待人工登录。

## 9. 客户端部署

1. 将客户端 EXE 和现场配置复制到本地磁盘，不要直接从光盘运行。
2. 确认 `server_base_url` 指向科研网服务器，例如 `http://10.0.0.12:9000/api`。
3. 启动 `FlightAnalyzer.exe`。
4. 使用服务器账号完成第一次在线登录。
5. 在同步页面确认服务器状态为 `online`。
6. 执行一次拉取或完整同步，检查机型、用户权限和数据。

### WebView2 Runtime

客户端使用 pywebview 的 Edge Chromium 后端，因此目标 Win10 必须有 Microsoft Edge WebView2 Runtime。新版 Windows/Edge/Office 环境通常已安装，但 Win10 LTSC、精简镜像或长期离线镜像不保证具备。

- 已安装 WebView2：只需部署 `FlightAnalyzer.exe`。
- 未安装 WebView2：通过光盘运行 64 位 WebView2 离线安装包。
- WebView2 安装包是环境兜底，不是 Flight Analyzer 每次运行所需的伴随文件。

建议在科研网标准 Win10 镜像上预先验证，再决定是否把安装包放入正式光盘。

### SHA256.txt

SHA256 文件不是运行依赖，只用于验证光盘刻录和跨安全区传输后的文件完整性：

```powershell
Get-FileHash .\FlightAnalyzer.exe -Algorithm SHA256
Get-FileHash .\FlightAnalyzerServer.exe -Algorithm SHA256
```

服务端构建脚本会自动生成 `SHA256.txt`。客户端可在制品发布时使用同一命令生成。如果单位已有制品签名和完整性校验流程，可以不额外携带该文件。

## 10. 验收清单

服务器本机：

```powershell
Get-Service MySQL80
Invoke-RestMethod http://127.0.0.1:9000/api/health
```

科研网客户端：

```powershell
Test-NetConnection 10.0.0.12 -Port 9000
Invoke-RestMethod http://10.0.0.12:9000/api/health
```

应用内检查：

- 客户端可以打开，无 WebView2 错误。
- 服务器状态为 `online`。
- 默认管理员密码已修改。
- 正式用户可以登录且权限正确。
- 预置机型、数据类型和列定义完整。
- 可以导入一组测试飞行数据。
- 可以完成上传、拉取和再次离线登录。
- 服务器和客户端数据目录均有足够空间及正确权限。

## 11. 数据、备份与升级

客户端默认数据：

```text
%APPDATA%\FlightAnalyzer\data.db
%APPDATA%\FlightAnalyzer\raw_files\
```

服务端数据包括：

- MySQL `flight_analyzer` 数据库。
- `[server].data_dir` 下的原始文件、传入包和生成包。
- 服务器目录中的 `flight_analyzer.ini`。

备份必须同时覆盖 MySQL 和服务端数据目录。只备份其中一项不能完整恢复系统。

升级顺序：

1. 停止客户端同步操作。
2. 备份 MySQL、服务端数据目录和配置文件。
3. 停止旧服务端 EXE。
4. 替换 `FlightAnalyzerServer.exe`，保留外部配置和数据目录。
5. 启动并验证健康接口。
6. 分批替换客户端 EXE。
7. 执行导入、查询和同步回归检查。

不要删除客户端 `%APPDATA%\FlightAnalyzer` 或服务端 `data_dir`，除非明确执行数据重置。

## 12. 常见问题

### 服务器 EXE 一启动就退出

先执行：

```powershell
.\FlightAnalyzerServer.exe --check-config
```

然后检查 MySQL 服务、数据库账号密码、数据目录权限，以及端口是否被占用。服务端 EXE 保留控制台窗口，启动异常会直接输出。

### 服务器本机健康检查成功，客户端失败

检查：

- `[server].host` 是否为 `0.0.0.0`。
- Windows 防火墙是否放通 TCP `9000`。
- 客户端地址是否带 `/api`。
- 科研网交换机、VLAN 或终端安全策略是否阻止访问。

### 客户端窗口打不开

优先检查 WebView2 Runtime。若标准镜像没有安装，使用光盘中的 64 位离线安装包安装后重试。

### 用户在断网时无法首次登录

这是预期行为。正式用户应至少在服务器可用时成功登录一次，以便客户端缓存离线验证信息。不要通过把正式密码哈希写进客户端种子来绕过这一流程。
