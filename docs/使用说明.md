# Flight Analyzer 使用说明

Flight Analyzer 是用于飞行数据导入、管理与分析的软件。当前说明文档暂包含导入、数据管理、数据分析三部分。



## 1. 导入数据

导入功能用于把外部飞行数据文件导入软件数据库，并建立“机型 - 飞机 - 飞行架次”的管理层级。导入时软件会自动扫描文件夹，识别数据类型、飞行场次、飞机序号和飞行日期，并在导入前提供预览。

导入后，软件会保存解析后的数据，同时转存本次导入关联的原始文件，便于后续追溯。

### 1.0 数据目录要求

导入路径必须是一个文件夹，不能直接选择单个文件。软件会递归扫描该文件夹下的 `.txt` 数据文件。

目录中必须存在一个以 8 位日期开头的日期目录，日期格式为 `YYYYMMDD`。推荐目录结构如下：

```text
20250323_test_flight/
  Aircraft001/
    xxx_120001.txt
    xxx_120002.txt
  Aircraft002/
    xxx_130001.txt
    xxx_130002.txt
```

目录规则说明：

- 日期目录名称必须以 `YYYYMMDD` 开头，例如 `20250323`、`20250323_test_flight`。
- 飞机序号建议放在日期目录的下一层，例如 `20250323_test_flight/Aircraft001/`，此时不同飞机的架次将能够直接识别并预填。
- 数据文件可以继续放在飞机目录下的子目录中，软件会递归扫描。
- 软件会从日期目录提取默认飞行日期，并从日期目录下一层目录提取飞机序号。
- 如果目录中没有检测到日期目录，扫描会失败，需要先整理目录结构。
- **如果日期目录下没有飞机序号子目录，软件可能无法自动分配飞机，需要在导入界面手动选择或创建飞机**。

### 1.1 使用流程

1. 进入“导入数据”页面。
2. 在路径输入框中填写飞行数据文件夹路径并点击"**扫描**"，或点击"**浏览**"选择文件夹。
3. 查看扫描结果，确认目录日期、飞机序号、识别到的数据类型和场次数量。
4. 机型选择：
  - 如果匹配到已有机型，可直接使用推荐机型。
  
     ![image-20260715162028370](asset/image-20260715162028370.png)
  - 如果发现新格式，会自动新建机型，需要输入机型名称，选择要保留的数据类型，然后点击"**创建机型并继续**"。
    > 注意，机型新建将根据当前目录中的数据文件构建，若存在当前批次数据文件均无表头的情况，则该机型的列定义部分也将缺少表头。
    > ![image-20260715161953903](asset/image-20260715161953903.png)
5. 对每个待导入架次确认飞机、飞行日期和飞行记录单。若架次包含FlightRecord.xml文件，会自动预填飞行记录单
![image-20260715162133599](asset/image-20260715162133599.png)
6. 点击对应场次的“**导入**”按钮，导入完整。
7. 导入完成后，可在“已导入飞行”列表中查看结果。
![image-20260715163754088](asset/image-20260715163754088.png)

### 1.2 飞行记录单 XML 格式

推荐格式如下，数值字段可留空；字段名也可以直接使用数据库字段名，例如 `record_location`、`record_weather`。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<FlightRecord>
  <BatchName>第一批</BatchName>
  <TotalDurationMin>75</TotalDurationMin>
  <Location>试飞场A区</Location>
  <Weather>晴</Weather>
  <Payload>2.5</Payload>
  <FuelAmount>18.0</FuelAmount>
  <TakeoffWeight>52.3</TakeoffWeight>
  <Altitude>1200</Altitude>
  <WindSpeed>3.2</WindSpeed>
  <WindDirection>3.2</WindDirection>
  <Note>自动预填示例</Note>
</FlightRecord>
```

字段对应关系：

- `TotalDurationMin` / `record_total_duration_min`：总时长，单位分钟。
- `Location` / `record_location`：地点。
- `Weather` / `record_weather`：天气。
- `Payload` / `record_payload`：设备载荷，按表单单位填写。
- `FuelAmount` / `record_fuel_amount`：燃油量，单位 kg。
- `TakeoffWeight` / `record_takeoff_weight`：起飞重量，单位 kg。
- `Altitude` / `record_altitude`：海拔高度，单位 m。
- `WindSpeed` / `record_wind_speed`：风速，单位 m/s。
- `WindDirection`：风向
- `Note` / `record_note`：备注。

## 2. 数据管理

数据管理用于维护已导入数据的组织结构、基础信息和列定义。主要管理对象包括机型、飞机、飞行架次、原始文件和数据列。

![image-20260722135754314](asset/image-20260722135754314.png)

### 主要功能

- 查看全局统计信息，包括总飞机数、总架次和总航时。
- 按机型查看飞机列表和对应飞行架次。
- 添加、重命名或删除飞机。
- 重命名或删除飞行架次。
- 编辑飞行记录信息，包括地点、天气、载荷、燃油、起飞重量、海拔、风速和备注。
- 查看某个飞行架次关联的原始文件清单，并打开原始文件目录。
- 查看和编辑列定义，包括数据组名称、字段显示名称和单位。
- 导出或导入同步包（`.fapkg`）：导出时选择架次生成离线同步包，导入时先预览包内容再确认机型处理、飞机映射和重复架次策略。
- 按飞机代号、时间范围、地点、天气、载荷等条件筛选数据。

# Flight Analyzer 部署

本文档面向科研网现场部署人员，假设开发人员已按《部署准备》完成打包并交付光盘。环境为无法访问互联网的 Windows 10 科研网；服务器使用 MySQL 8，客户端使用本地 SQLite。

## 1. 光盘内容

收到的光盘目录结构：

```text
FlightAnalyzer-Release\
├── Client\
│   ├── FlightAnalyzer.exe
│   ├── flight_analyzer.ini
│   ├── 使用说明.pdf
├── Server\
│   ├── FlightAnalyzerServer.exe
│   ├── start-server.ps1
│   ├── initialize-mysql.ps1
└── MySQL\
    └── MySQL 8.x 64 位完整离线安装包
```

标准部署不携带任何 `flight_analyzer.ini`，所有配置已内置在 EXE 中。`Server` 和 `ServerAdmin` 由管理员单独传入内网，`ServerAdmin` 不进入用户可访问的共享位置。

## 2. 服务器部署

### 2.1 安装 MySQL

使用完整离线安装包安装 MySQL Server 8.x，并设置为 Windows 自动启动服务。常见服务名为 `MySQL80`，以现场安装结果为准。只需首次安装一次，以后启动服务器不要再运行 MySQL 安装程序。

### 2.2 初始化数据库和应用账号

把 `Server` 目录复制到服务器本地磁盘，并通过以下两种方式初始化数据库。

#### 方式一：PowerShell 脚本（默认）

以管理员 PowerShell 执行：

```powershell
.\Server\initialize-mysql.ps1
```

脚本依次提示输入并确认构建期 `[mysql].password`，再输入安装 MySQL 时设置的管理员密码，两个密码都不会写入生成的脚本。随后按打包参数执行幂等操作：检查并启动 `MySQL80` 服务、创建 `flight_analyzer` 数据库、创建或校准仅允许本机登录的应用账号及密码、授予该账号对业务数据库的权限。



#### 方式二：手动 SQL（无法执行 PowerShell 时）

适用于科研网服务器无法执行 PowerShell 脚本的情况。在 PowerShell 中启动 MySQL 命令行客户端，以 `root` 等管理员账号执行 SQL。

执行前确认参数与构建 `FlightAnalyzerServer.exe` 时的 `[mysql]` 一致：

```text
数据库：flight_analyzer
应用账号：flight
账号主机：127.0.0.1
字符集：utf8mb4
排序规则：utf8mb4_unicode_ci
```

**连接 MySQL。** 检查服务并启动：

```powershell
Get-Service -Name MySQL80
Start-Service -Name MySQL80      # 仅当状态不是 Running 时
```

连接数据库（路径以实际安装为准）：

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" `
  --protocol=TCP `
  --host=127.0.0.1 `
  --port=3306 `
  --user=root `
  --password
```

若 `mysql.exe` 已加入 `PATH`，可直接：

```powershell
mysql --protocol=TCP --host=127.0.0.1 --port=3306 --user=root --password
```

出现 `Enter password:` 后输入 `root` 密码（输入不显示字符），看到 `mysql>` 即连接成功。确认连接：

```sql
SELECT VERSION();
SELECT CURRENT_USER();
```

> 上述命令只是启动 `mysql.exe`，不是执行 `.ps1`，通常不受 PowerShell 脚本执行策略限制。也可用 MySQL Workbench 连接 `127.0.0.1:3306` 执行相同 SQL。

**初始化 SQL。** 用于首次部署或账号尚未创建时，重复执行不删除业务数据。将 `CHANGE_ME` 替换为构建期 MySQL 应用密码（密码含反斜杠写 `\\`，含单引号写两个单引号 `''`）：

```sql
CREATE DATABASE IF NOT EXISTS `flight_analyzer`
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'flight'@'127.0.0.1'
  IDENTIFIED BY 'CHANGE_ME';

ALTER USER 'flight'@'127.0.0.1'
  IDENTIFIED BY 'CHANGE_ME';

GRANT ALL PRIVILEGES ON `flight_analyzer`.*
  TO 'flight'@'127.0.0.1';

FLUSH PRIVILEGES;
```

检查结果：

```sql
SHOW DATABASES LIKE 'flight_analyzer';
SHOW GRANTS FOR 'flight'@'127.0.0.1';
EXIT;
```

初始化成功后，从服务器删除临时复制的 `ServerAdmin` 目录，继续在受控位置保管管理员制品。不要让客户端访问 MySQL，也不需要对科研网开放 TCP `3306`。

### 2.3 启动

管理员 PowerShell 进入服务器目录：

```powershell
.\start-server.ps1
```

若 PowerShell 脚本无法执行，可手动启动：先在管理员 PowerShell 中启动 MySQL 服务，再双击运行 `FlightAnalyzerServer.exe`。

```powershell
Start-Service -Name MySQL80
```

默认行为：检查并启动 `MySQL80` 服务、检查 `http://127.0.0.1:9000/api/health` 是否已有实例、启动 `FlightAnalyzerServer.exe`、30 秒内轮询健康接口。

首次启动自动创建业务表和内置管理员：

```text
用户名：admin
初始密码：123456
```

### 2.4 MySQL自动启动

MySQL 配置为 Windows 自动启动服务。`FlightAnalyzerServer.exe` 开机启动可选：Windows 任务计划程序（专用账号，系统启动时运行）、单位批准的 Windows 服务包装器、或人工运行 `start-server.ps1`。正式环境推荐任务计划或 Windows 服务，避免重启后等待人工登录。



## 3. 客户端部署

启动 `FlightAnalyzer.exe`。

若需要修改配置，在.exe同目录下，新建`flight_analyzer.ini`，内容如下。

- data_dir：客户端数据存放路径，可自行修改，以下为默认路径。
- server_base_url：请求服务器地址，将127.0.0.1切换为服务器IP地址

```text
[local]
data_dir = C:\Users\用户名\AppData\Roaming\FlightAnalyzer
server_base_url = http://127.0.0.1:9000/api
```



## 4. 重置

### 4.1 客户端重置

删除该路径下的所有文件

```
C:\Users\用户名\AppData\Roaming\FlightAnalyzer
```

> 此路径为默认`data_dir`路径，若在【3. 客户端重置】中修改了`data_dir`路径，则应该删除修改后`data_dir`路径下的所有文件



### 4.2 服务器重置

- 删除该路径下的所有文件
  ```
  %APPDATA%\FlightAnalyzerServer
  ```
  > 此路径为默认`data_dir`路径，若在【3. 客户端重置】中修改了`data_dir`路径，则应该删除修改后`data_dir`路径下的所有文件
- 清空mysql数据库

  永久删除 MySQL 中全部 Flight Analyzer 数据和旧表结构。执行前先停止 `FlightAnalyzerServer.exe`。按 2.2 方式二连接 MySQL 后，将 `CHANGE_ME` 替换为新版应用密码，完整执行：
