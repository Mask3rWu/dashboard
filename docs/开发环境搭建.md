# Flight Analyzer 开发环境搭建与交接

本文档面向接手项目的开发人员，说明如何在本地重建 Flight Analyzer 的客户端、服务端和前端开发环境。

项目根目录中的 `.venv` 和 `.venv-server` 是本机生成的 Python 虚拟环境，包含与创建机器相关的解释器路径和已安装文件，因此不应复制给其他开发者，也不应提交到 Git。两个目录均已在 [`.gitignore`](../.gitignore) 中排除。接手者应使用仓库中的依赖文件重新创建环境。

## 1. 环境用途


| 目录             | 用途              | 依赖文件                                                        |
| -------------- | --------------- | ----------------------------------------------------------- |
| `.venv`        | 桌面客户端开发、运行和打包   | `requirements.txt`                                          |
| `.venv-server` | 独立协作服务器开发、运行和打包 | `requirements-server.txt` 或 `requirements-server-build.txt` |


两套环境分离的主要目的是避免把 SQLAlchemy、PyMySQL 等服务端专用依赖带入桌面客户端的 PyInstaller 构建，减小打包体积并降低依赖冲突风险。

当前环境使用 Python 3.12.3。开发者可以使用标准 CPython 3.12，不要求安装 Anaconda。

## 2. 前置工具

在 Windows 开发机上安装：

- 64 位 Python 3.12，并确保 `py -3.12` 可用。
- Node.js 和 npm，用于 React 前端开发与构建。
- Git。
- 如需运行协作服务器，准备可连接的 MySQL 8.x 实例。

以下命令均在项目根目录执行：

```powershell
Set-Location D:\Projects\dashboard
```

实际克隆路径可以不同，但后续命令应在对应项目根目录执行。

## 3. 创建桌面客户端环境

创建 `.venv` 并安装客户端运行及打包依赖：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

不必先激活环境。脚本会直接使用 `.venv` 中的程序。需要在当前 PowerShell 会话中交互开发时，也可以激活：

```powershell
.\.venv\Scripts\Activate.ps1
```

安装完成后可以检查解释器及关键依赖：

```powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -c "import fastapi, uvicorn, webview; print('client environment ready')"
```

## 4. 创建独立服务端环境

如果需要运行并打包服务端，推荐安装构建依赖。`requirements-server-build.txt` 已包含服务端运行依赖和 PyInstaller：

```powershell
py -3.12 -m venv .venv-server
.\.venv-server\Scripts\python.exe -m pip install --upgrade pip
.\.venv-server\Scripts\python.exe -m pip install -r requirements-server-build.txt
```

安装完成后检查关键依赖：

```powershell
.\.venv-server\Scripts\python.exe --version
.\.venv-server\Scripts\python.exe -c "import fastapi, uvicorn, sqlalchemy, pymysql, multipart; print('server environment ready')"
```

如果只需要从源码运行服务端、不需要使用 PyInstaller 打包，可以安装更小的运行依赖集合：

```powershell
.\.venv-server\Scripts\python.exe -m pip install -r requirements-server.txt
```

## 5. 安装开发与测试依赖

`requirements-dev.txt` 汇总了客户端、服务端和测试依赖。需要运行完整测试集时，可以将其安装到 `.venv`：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

该操作会使 `.venv` 同时包含服务端依赖。日常只开发或打包桌面客户端时，使用 `requirements.txt` 即可，以维持最小依赖环境。

运行测试：

```powershell
.\.venv\Scripts\python.exe -m pytest
```

## 6. 安装前端依赖

前端依赖不在 Python 虚拟环境中，需要单独安装：

```powershell
Set-Location .\frontend
npm install
Set-Location ..
```

启动 Vite 开发服务：

```powershell
Set-Location .\frontend
npm run dev
```

## 7. 运行与打包

### 桌面客户端

构建前端并启动桌面客户端：

```powershell
.\script\run.ps1
```

构建前端并生成桌面客户端 EXE：

```powershell
.\script\build.ps1
```

输出位置：

```text
packaging\dist\FlightAnalyzer.exe
```

### 独立协作服务器

从源码启动服务器：

```powershell
.\script\run-server.ps1
```

生成独立服务器程序：

```powershell
.\script\build-server.ps1
```

主要输出位置：

```text
packaging\dist\server\FlightAnalyzerServer.exe
```

服务端脚本默认使用 `.venv-server`。需要使用其他环境路径时，可以通过参数指定：

```powershell
.\script\run-server.ps1 -ServerVenv D:\path\to\server-venv
.\script\build-server.ps1 -BuildVenv D:\path\to\server-venv
```

## 8. 重建环境

虚拟环境损坏、Python 版本变化或依赖状态不可确认时，应删除对应虚拟环境目录并按本文重新创建，不要在不同开发机之间复制虚拟环境。

重建前应确认没有进程正在使用该环境。删除 `.venv` 或 `.venv-server` 不会删除项目源代码和业务数据，但会清除该环境中本地安装的所有 Python 包。

## 9. 补充：脚本说明

## 9.1 在新环境中运行 PowerShell 脚本

新电脑首次运行 `.ps1` 报"禁止运行脚本"或"未数字签名"时，执行一次：

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

若脚本是从 GitHub 网页 "Download ZIP" 下载解压的（git clone 拉取的无需此步），再执行：

```powershell
Get-ChildItem script\*.ps1 | Unblock-File
```

## 9.2 脚本一览

均在项目根目录执行。

### `run.ps1` -- 启动桌面客户端（开发）

```powershell
.\script\run.ps1
```

构建前端 + 运行 `main.py`。

### `run-server.ps1` -- 启动协作服务器（开发）

```powershell
.\script\run-server.ps1
```

用 `.venv-server` 运行 `server_main.py`。

### `build.ps1` -- 打包桌面客户端

```powershell
.\script\build.ps1
```

产物：`packaging/dist/FlightAnalyzer.exe`。

### `build-server.ps1` -- 打包协作服务器

```powershell
.\script\build-server.ps1
```

产物：`packaging/dist/server` 与 `server-admin`。

### `generate_builtin_model_seeds.py` -- 生成内置种子

```bash
.venv\Scripts\python.exe script\generate_builtin_model_seeds.py
```

从服务端拉取机型/用户，生成 `backend/builtin_model_seeds.json`。

### `reset_project_data.py` -- 重置测试数据

```bash
.venv\Scripts\python.exe script\reset_project_data.py            # 查看将清理什么
.venv\Scripts\python.exe script\reset_project_data.py --yes      # 实际执行
```

默认 dry-run，加 `--yes` 才真正清除。

### `start-server.ps1` / `initialize-mysql.ps1`

随服务端打包产物分发，供现场部署使用，开发流程不直接调用。
