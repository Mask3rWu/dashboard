# Flight Analyzer 部署准备（开发人员）

本文档面向开发人员，描述在构建机上完成代码冻结、机型预置、客户端与服务器打包、制作光盘的完整流程。现场部署由《部署》文档另行说明。

目标环境：通过光盘把 Flight Analyzer 部署到无法访问互联网的 Windows 10 科研网。客户端与服务器均为独立 EXE；客户端使用本地 SQLite，统一服务器使用 MySQL。

## 1. 部署架构

```text
客户端 Windows 10                         科研网服务器 Windows 10
┌────────────────────────┐               ┌──────────────────────────┐
│ FlightAnalyzer.exe     │   HTTP 9000   │ FlightAnalyzerServer.exe │
│ React + FastAPI        │ ────────────> │ FastAPI / 同步服务        │
│ pywebview              │               │                          │
│ SQLite 本地缓存         │               │ MySQL 8 权威数据库         │
└────────────────────────┘               └──────────────────────────┘
```

- 客户端不需要 Python、Node.js 或 MySQL。
- 服务器不需要 Python，但必须安装 MySQL 8.x。
- 客户端只访问服务器 TCP `9000`，不直接访问 MySQL `3306`。
- MySQL 应只监听服务器本机或由防火墙限制为仅服务器应用可访问。

如不需多机共享同步，可只部署 `FlightAnalyzer.exe`：客户端 `server_base_url` 留空，数据全部存本地 SQLite。

## 2. 总体顺序

```text
1. 冻结待发布代码版本
2. 在制品环境定稿机型
3. 生成内置机型 seed
4. 在项目根目录定稿唯一一份构建期 flight_analyzer.ini
5. 打包客户端 EXE
6. 打包服务器 EXE
7. 制作光盘并记录 SHA256
8. 科研网服务器安装、初始化 MySQL     ← 之后交给《使用说明》文档的部署章节
9. 部署并启动 FlightAnalyzerServer.exe
10. 修改默认管理员密码并创建正式用户
11. 部署客户端 EXE
12. 用户首次在线登录、同步和验收
```

本文档覆盖 1–7 步。机型预置必须在打包之前完成；正式用户在服务器部署完成后创建，不要把用户密码或哈希嵌入客户端 EXE。

## 3. 构建机准备

构建必须在与目标机架构一致的 Windows 环境进行。目标为 64 位 Windows 10，因此使用 64 位 Python 和 PyInstaller。

```powershell
# 客户端构建及运行依赖
.\.venv\Scripts\pip.exe install -r requirements.txt

# 独立的最小服务端构建环境，不要复用客户端或 Anaconda 全量环境
py -3.12 -m venv .venv-server
.\.venv-server\Scripts\pip.exe install -r requirements-server-build.txt

# 前端依赖
Set-Location .\frontend
npm install
Set-Location ..
```

构建机可联网准备依赖；科研网目标机不需要这些开发工具。

## 4. 机型预置

在制品服务器中维护并确认所有机型、数据类型、列定义和解析规则。项目根目录准备临时 `flight_analyzer.ini`：`[local].server_base_url` 指向制品服务器，`[server_auth]` 填写有读取权限的账号。

```powershell
.\.venv\Scripts\python.exe .\script\generate_builtin_model_seeds.py
```

输出 `backend\builtin_model_seeds.json`。随后再打包客户端和服务器，同一版客户端与服务器使用同一份 seed。首次启动时：客户端把缺失机型写入本地 SQLite，服务器写入 MySQL；已有相同 `server_id`、`client_uid` 或名称的机型不会被覆盖。

### 用户预置说明

不要用 `builtin_model_seeds.json` 预置正式用户：

- 服务器用户列表 API 不返回密码哈希，生成文件中 `password_hash` 为 `null`。
- 本地种子加载器会跳过没有密码哈希的用户。
- 手工补充密码哈希有 EXE 可提取、离线破解风险。
- 加载逻辑每次启动会更新有效用户种子，会覆盖本地改密结果。

推荐：服务器部署完成后创建用户，每名用户在服务器可用时至少成功登录客户端一次，客户端缓存验证信息后即可离线登录。

## 5. 打包客户端

在项目根目录构建期 `flight_analyzer.ini` 中定稿 `[local].server_base_url`。打包只嵌入 `[local]` 和 `[dev]`，不嵌入 `[server]`、`[mysql]`、`[server_auth]` 或 MySQL 密码。

```powershell
.\script\build.ps1
```

输出 `packaging\dist\FlightAnalyzer.exe`。标准部署只复制该 EXE，客户端直接使用打包配置，不需要在 EXE 同目录另放 `flight_analyzer.ini`。构建前确认：

```ini
[local]
; 建议留空，让不同 Windows 用户使用各自的 %APPDATA%\FlightAnalyzer
data_dir =
server_base_url = http://10.0.0.12:9000/api
```

注意：

- 地址必须带 `/api`。
- `data_dir` 必须允许当前 Windows 用户读写；留空时不同 Windows 账号使用各自 `%APPDATA%`。
- 只有需要临时覆盖已打包地址的特殊场景，才在 EXE 同目录放外部 `flight_analyzer.ini`，它不是标准部署制品。

## 6. 打包服务器

打包前在同一份 `flight_analyzer.ini` 中定稿服务端和 MySQL 参数：

```ini
[server]
host = 0.0.0.0
port = 9000
data_dir = %APPDATA%\FlightAnalyzerServer

[mysql]
host = 127.0.0.1
port = 3306
database = flight_analyzer
user = flight
password = 每个发布环境单独生成的强密码
user_host = 127.0.0.1
charset = utf8mb4
collation = utf8mb4_unicode_ci
```

`%APPDATA%` 会在服务端启动时展开为当前 Windows 运行账号的 `AppData\Roaming` 目录。

打包部署不支持用 `[mysql].url` 初始化数据库，须用以上分字段配置。根目录 `flight_analyzer.ini` 已被 Git 忽略，不应提交真实密码。

```powershell
.\script\build-server.ps1
```

脚本默认用独立 `.venv-server`，只装服务器运行依赖和 PyInstaller。不要把 pywebview、openpyxl、pytest 等装进该环境。脚本会检查依赖、运行 PyInstaller、执行无数据库运行时检查，并输出：

```text
packaging\dist\server\
├── FlightAnalyzerServer.exe
├── start-server.ps1
└── SHA256.txt

packaging\dist\server-admin\
├── initialize-mysql.ps1
└── SHA256.txt
```

服务端 EXE 包含 Python、FastAPI、uvicorn、SQLAlchemy、PyMySQL、同步服务代码、内置机型 seed，以及从根目录配置提取的 `[server]`、`[mysql]`、`[dev]`。不含 `[local]`、`[server_auth]`、React 前端、pywebview 或 WebView2。

`server` 是日常运行制品，可长期留在服务器；`server-admin` 是一次性管理员制品，不应分发给客户端用户或放入普通共享目录。`initialize-mysql.ps1` 默认使用 `127.0.0.1:3306`、数据库 `flight_analyzer`、账号 `flight@127.0.0.1`，应用密码和 MySQL 管理员密码均在执行时安全输入，现场不需要第二份 INI。

服务端 EXE 内置配置包含 MySQL 应用密码。应使用 Windows ACL 限制服务器目录只允许服务运行账号和管理员读取；若普通用户也能读取服务端 EXE，内置密码不能视为不可提取的秘密。

需要其他最小虚拟环境时：

```powershell
.\script\build-server.ps1 -BuildVenv D:\BuildEnvs\flight-server
```

构建后可在无 MySQL 的构建机上执行无数据库检查：

```powershell
.\packaging\dist\server\FlightAnalyzerServer.exe --check-runtime
```

输出配置路径、监听地址、数据目录、数据库驱动和 API 路由数量；会加载 `mysql+pymysql` 方言但不建立 MySQL 网络连接，也不输出密码。只检查配置用 `--check-config`。

## 7. 光盘内容

推荐光盘目录：

```text
FlightAnalyzer-Release\
├── Client\
│   ├── FlightAnalyzer.exe
│   ├── 使用说明.pdf
├── Server\
│   ├── FlightAnalyzerServer.exe
│   ├── 部署说明.pdf
│   ├── start-server.ps1
│   ├── initialize-mysql.ps1
└── MySQL\
    └── MySQL 8.x 64 位完整离线安装包
```

标准部署不携带任何 `flight_analyzer.ini`。面向普通用户的介质只含 `Client`；`Server` 和 `ServerAdmin` 由部署管理员单独传入内网，`ServerAdmin` 不进入用户可访问的共享位置。发布参数变化时，回构建机改配置重新打包。运行时仍支持外部 INI 或环境变量覆盖，仅作故障处理或特殊部署手段。

后续现场部署见《部署》文档。
